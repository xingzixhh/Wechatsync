# 本地开发与测试

> 本工具本质是 **Chrome / Edge 扩展**：改代码后必须在浏览器里「加载已解压的扩展程序」才能测。没有单独的网页预览能代替扩展联调。

## 一、环境

- Node.js **≥ 20**
- 包管理器用 **pnpm**（根目录 `package.json` / README 以 pnpm 为准；根目录 `CONTRIBUTING.md` 偏旧，可忽略 yarn 那套）
- Chromium 内核浏览器：Chrome 或 Edge

## 二、第一次搭起来

在仓库根目录：

```powershell
cd E:\00_code\99_self\Wechatsync
pnpm install
pnpm build:extension
```

产物目录：

```
E:\00_code\99_self\Wechatsync\packages\extension\dist
```

### 加载扩展（只做一次；以后改代码多半是刷新）

1. 打开 `chrome://extensions`（Edge 用 `edge://extensions`）
2. 打开右上角「开发者模式」
3. **关掉 / 卸掉** Chrome 应用店里已装的「文章同步助手」（避免和本地开发版抢权限、搞混登录态）
4. 点「加载已解压的扩展程序」
5. 选中上面的 `packages\extension\dist` 目录
6. 确认扩展列表里出现你加载的那一项

## 三、日常改代码怎么测

### 方式 A：开发模式（推荐改 UI / 文案）

```powershell
cd E:\00_code\99_self\Wechatsync
pnpm dev
```

- 会持续编译扩展到 `packages/extension/dist`
- 改完源码后：到扩展管理页点该扩展的 **「重新加载」**（圆形刷新图标）
- 若改的是 popup：关掉再点一次扩展图标
- 若改的是 content script / 页面悬浮按钮：打开的业务网页也要 **刷新**

### 方式 B：正式构建后再测

```powershell
pnpm build:extension
```

然后同样在扩展管理页点「重新加载」。发 zip、给别人装、或怀疑 dev 缓存脏了时用这个。

## 四、改完「名字 / 品牌」时的最小验收（不测发文）

只改展示名、描述、图标时，按这个清单点一遍即可：

1. 扩展管理页：扩展 **名称**、**描述** 是否已是公司文案
2. 浏览器工具栏：扩展图标是否已换成公司图标（必要时固定到工具栏）
3. 点扩展图标打开 popup：首页标题、关于页、页脚链接是否正确
4. 打开一篇任意文章页（例如博客园已发文）：页面上悬浮按钮 / 右键菜单文案是否正确
5. 打开同步对话框：标题、提示文案是否还有旧名

详细改哪些文件见 [`02_改品牌名清单.md`](./02_改品牌名清单.md)。

## 五、改完「同步逻辑」时的功能验收（真发草稿）

按你们运营约定：**先发博客园 → 再从博客园页同步到其他站草稿**。

1. 浏览器里登录目标站（知乎 / 掘金 / 头条 / 百家号等）
2. 打开一篇博客园已发文
3. 用扩展选平台 → 同步
4. 到各站 **草稿箱** 看：标题、正文、图片是否正常
5. **先别点发布**；确认草稿没问题再人工发布

注意：同步依赖你浏览器里已有的登录 Cookie；扩展不替你登录。

## 六、可选：单元测试 / 类型检查

```powershell
# 扩展包 vitest（有的话）
pnpm --filter @wechatsync/extension test

# 类型检查
pnpm typecheck
```

这些过了也不能代替「浏览器里加载扩展」；品牌文案、同步链路仍以浏览器手测为准。

## 七、常见坑

| 现象 | 常见原因 |
|------|----------|
| 改了代码界面没变 | 忘了扩展管理页「重新加载」；或页面没刷新 |
| 两个「同步助手」同时存在 | 商店版 + 本地版都开着，关掉商店版 |
| 同步提示未登录 | 该平台网页没登录，或 Cookie 被清了 |
| `pnpm install` 报 Node 版本 | 升级到 Node 20+ |
| 私有适配器缺失 | 上游有 `private-adapters` 子模块（需权限）；公开平台一般不受影响 |
